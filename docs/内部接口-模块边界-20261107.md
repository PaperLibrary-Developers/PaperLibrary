# Nexus 内部接口与模块边界（协作规约）

> 目的：多人（多智能体）并行时，**文件所有权不重叠、接口不猜**。
> 任何跨模块的新需求：先发消息给 Lead，由 Lead 改 paperlib/routes.py 或 paperlib/services.py，其他人不要动这两个文件。

## 1. 分层与依赖方向

    public/（浏览器）
      → /api/*（同源 HTTP）
    paperlib/http/（server/router/static/sse）
      → paperlib/routes.py（唯一路由表）
        → paperlib/api/*（入参校验 + 组响应）
          → paperlib/domain/*（业务规则）
            → paperlib/data/*（SQLite 唯一真源） 与 paperlib/adapters/*（I/O）
    shared/pure/*.py（纯函数，零 I/O；api/domain 都可以 import）

硬规则：
- 依赖只能向下（api → domain → data/adapters），domain 不 import api，data 不 import api/domain。
- SQL 只允许出现在 paperlib/data/repository.py。
- 纯函数（无 I/O、无全局态）放 shared/pure/，并且必须有对照测试。
- 单文件 ≤600 行（目标是 ≤450）。

## 3. 已就绪的地基（可直接用）

### 3.1 Ctx（paperlib/http/server.py）

    ctx.method / ctx.pathname / ctx.params / ctx.query(name, default) / ctx.query_all(name)
    ctx.read_body(limit) -> bytes          # 原始流（上传；X-Filename 头在 ctx.headers）
    ctx.read_json(limit) -> Any            # 空体返回 {}；非法 JSON 抛 ValueError
    ctx.json(status, data)                 # JSON 响应（自动 Content-Length，HEAD 无体）
    ctx.fail(status, message, extra=None)  # {ok:false, error}
    ctx.text(status, text, content_type=None)
    ctx.send_bytes(status, data, content_type, headers=None)
    ctx.send_file(abs_path, inline=None, download=None, cache=None, content_type=None)
                                           # Range 206 / ETag 304 / 416，全部已实现
    ctx.start_stream(status, headers) / write_chunk(bytes) / end_stream()
                                           # SSE 用 paperlib/http/sse.py 的 SseStream(ctx)
    ctx.services                            # 依赖注入容器（见 3.4）

## 4. 响应形状与错误约定（api 层）

- 成功：200/201，JSON 对象且 ok:true；错误：{ok:false,error:"中文可读消息"}。
- 方法不匹配：只有设置类 4 个端点回 405「不支持的请求方法」；其余方法不匹配由路由层回 404「接口不存在：<path>」。
- 状态码：400 参数/业务校验；404 资源不存在；409 冲突；413 上传超限；501 可选依赖缺失；502 外部服务失败；206/304/416 文件与条件请求。
- SSE：用 SseStream(ctx)；帧 {"type":"start|delta|sources|done|error"}；参数校验在开流之前完成。
- 上传：X-Filename（URL 编码）、X-Paper-Id；原始字节流，不要 multipart。
- Content-Disposition：Ctx.send_file 会对 inline/download 文件名做 percent-encoding（对齐 Node encodeURIComponent），调用方**不要再 quote**。
- 契约勘误（以 Node 实现为准）：api.md §1.4 说附件下载用 attachment，实际 Node attachmentDownload 用 inline（前端用 <a href> 打开）；Python 保持一致，勿改成 attachment。
- 文件名一律过 util.safe_path_join。

## 5. 协作与测试规则

1. **只改自己范围内的文件**；需要改地基/路由/服务装配 → 发消息给 Lead，说明「要加什么属性/路由」。
2. 每个模块交付前跑：python -m unittest discover -s test -v（或自己的 test_*.py）。
3. 冒烟用独立端口与数据目录：python -m paperlib --port 439x --no-open --data-dir data-<角色>；不要占 4321。
4. 不 push；commit 信息写清模块与验收命令；每个角色完成时用 team_task_update 标 completed 并汇报。
5. 不引入第三方依赖（PyMuPDF/Pillow 已内置；HTTP 用 urllib，不用 requests）。
6. 行数 ≤600（硬）、≤450（目标）；每文件头写「移植自 <JS 路径>」与契约名。
7. 时间/编码：JSON 输出 ensure_ascii=False；时间用 util.now_iso()（ISO Z 格式）。
