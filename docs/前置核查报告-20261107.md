# 前置核查报告（开工前 3 项）

> 日期：2026-11-07 ｜ 范围：Nexus 合并仓开工前的三项核查
> 结论：**三项全部完成**；第 1 项发现 2 处「文档/快照口径差」需在验收时用 e2e 补足，已在批次 2 计划里加任务。

## 核查 1 · 60 端点规格是否完整

**结论：完整，但口径要从「60」改成「64 条唯一端点 + 69 条快照行」。**

| 口径 | 实测数字 | 说明 |
|---|---|---|
| 手册口径 | 60 条 | 草案阶段的估算，已过时 |
| shared/contracts/api.md §3 表格行 | **64 条** | 7 基础/运维 + 3 标签 + 29 文献 + 5 AI + 11 外部源 + 2 抓取 + 4 导入 + 3 导出 |
| server/routes.js 路由记录 | **58 条** | 一个记录可含多方法（PUT/PATCH、GET/HEAD）；/api/export/:kind 一条覆盖 3 个导出端点；4 个设置端点用 * 吞方法 |
| tools/api-snapshot.json 行数 | **69 行** | 56 条 API 快照 + 10 条 network/skip + 3 条静态/vendor（/、/vendor/pdfjs、/vendor/katex）|
| 静态/共享路由 | /、/styles.css、/main.mjs、/js/**、/shared/**、/vendor/pdfjs/**、/vendor/katex/** | api.md §1.5 已覆盖，不在 §3 表格里 |

**覆盖性核对（脚本逐条比对）**：api.md 的 64 条端点全部能在 58 条路由记录里命中；没有「只在路由表、不在契约」的端点；方法覆盖无缺口（设置类 4 条用 * + 自判 405，其余方法不匹配按 404「接口不存在」）。

**发现的 2 处口径差（不阻塞，但必须补测试）**：

1. api-snapshot.json 只记录**顶层 JSON 键 + 状态码类别**，不校验嵌套形状与字段值。Python 移植若只对齐顶层键，可能出现「形状对、字段错」的静默回归。
   → 批次 2 增加任务：**Node 参照响应全量 diff**（同一份 fixture 数据分别喂 Node 与 Python，逐字段比对，忽略时间戳/pid/路径）。
2. api.md 里 GET /api/papers/:id/pdf、/api/export/* 是 3 条导出合 1 条路由的写法，快照按 3 条记录。契约文档与快照的粒度不同，e2e 脚本要按「路径集合」比对，不能按行数比对。

**验收判定**：以 api.md §3 的 64 条为「端点清单」，以 e2e 的请求集合为「可执行清单」，两者对齐后才算通过。

## 核查 2 · public/main.mjs 与前端的实际接线点（ESM 之后）

**结论：前端是纯浏览器 ESM 资产，换 Python 后端零改动，只有 6 个接线点。**

| # | 接线点 | 实测 | Python 后端要做什么 |
|---|---|---|---|
| 1 | 唯一入口 | public/index.html 只有 1 个 script type=module src=/main.mjs；main.mjs 14 行，import js/app.mjs 的 boot() | 静态托管 + HTML 内 href/src 版本号重写（只认 styles.css、main.mjs、js/*） |
| 2 | API 同源 | js/api.mjs 346 行，33 个路径常量全部是 /api/...，无 baseURL | 同源实现 64 端点，形状按 api.md |
| 3 | 状态层 | js/state/store.mjs 100 行：getState/patch/subscribe，window.LV 已归零 | 无 |
| 4 | 视图层 | 6 视图 = list 370 + detail 1,512 + edit 883 + search 1,538 + settings 1,079 + timeline 108；shell app.mjs 458、shell/app-api.mjs 327 | 无（新增 3 视图只加路由与 api 方法） |
| 5 | pdfjs 资源 | js/vendor.mjs 默认 base：/vendor/pdfjs、/vendor/katex；pdfviewer.mjs 1,597 行用 pdfjs 浏览器构建（module + worker + cmaps + standard_fonts） | 静态托管 vendor/pdfjs/**、vendor/katex/**，缺失时 404（前端自动降级） |
| 6 | 共享内核 | public/main.mjs 与视图用**绝对路径** import /shared/html-text.mjs；shared/pure/*.js 只在 Node 侧 | /shared/** 静态路由；Python 侧对应 shared/pure/*.py（同语义） |

补充事实（开工基线）：
- public/ 22 文件 / 688 KB / 9,486 行 JS（含 pdfviewer）；main.mjs 依赖图 **0 环**（P4 已验收）。
- SSE 三处（总结/对话/识图）由 api.mjs 用 fetch 流解析 data: <json> 双换行；上传用 XHR 原始字节流 + X-Filename（URL 编码）头——Python 侧必须原样支持，不能换成 multipart。
- PDF 阅读器依赖 Range 分片（206）与 If-None-Match/ETag（304），Python 的静态/文件响应必须实现。
