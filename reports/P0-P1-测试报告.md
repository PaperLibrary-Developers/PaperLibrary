# PaperLibrary P0 与 P1 优化及测试报告

测试日期 2026-11-18（日本时间）

对照版本为发布后的 `565f1985`、P0 提交 `9149b45` 以及本轮 P1 工作区。测试使用 Windows 11 10.0.26200、Intel Core i7-14650HX、独立程序目录和合成文献库。性能测试使用便携 Python 3.11.9，前端测试使用 Edge 157 与 Node 24.21.0。

## 已完成的优化

| 优先级 | 实际改动 | 对使用者的影响 |
| --- | --- | --- |
| P0 · 文献写入 | 锁内读取最新卡片并合并字段。题录、标签、附件记录、对话和库更新时间在同一个 SQLite 事务提交。成功后才更新内存和索引。按最新记录追加附件和对话，附件上传采用独占文件创建。 | 同时编辑同篇的评分和阅读状态可以各自保存。某次写入失败时，界面不会留下假成功的卡片，后续保存也不会带入这次失败的修改。 |
| P0 · 升级和恢复 | 新版健康检查期间限制界面和常规 API。健康检查失败或安装中断时，先停新版，再校验并恢复数据库、SQLite 伴随文件和设置，最后恢复程序并打开旧版。损坏快照保留日志和重试入口。 | 试运行新版期间无法误编辑。恢复旧版时可继续读取升级前的文献和设置。同版本重试会重新备份，覆盖上次回滚后用户继续修改的情况。 |
| P1 · 大库装载 | 关联表从逐篇查询改为一张表一次。新增按加入时间读取所需的 SQLite 索引。保留卡片顺序、历史标签回退规则、附件顺序和对话顺序。 | 大库打开期间等待数据的时间缩短。已有库会在首次启动时建索引，原有分类、附件和对话继续使用。 |
| P1 · 单条编辑 | 延续 P0 的按卡片持久化，评分等题录变化跳过内容未变的标签、附件和对话表。 | 给长对话或多附件文献打分时，保存环节少做数据库工作。浏览器仍执行原有的页面刷新和反馈。 |
| P1 · 详情页生命周期 | 路由退出时清理全局监听、计时器、动画帧、拖拽样式、弹层和 PDF.js 加载任务。取消旧详情、附件列表等页面读取。已发出的保存和服务端生成任务仍可完成，旧页面停止更新。批注按文献串行落库。 | 快速切换时，旧加载失败不会盖掉当前文献。拖着分栏离开不会留下拖拽光标或禁用文本选择。 |
| P1 · Windows 验证 | 便携 Python ZIP 和两个 wheel 均校验 SHA-256。Windows CI 固定 Python、Node 和 Actions 版本。契约测试由操作系统分配端口，并核对服务 PID。临时 JSON 写入使用独立文件名并短暂重试 Windows 文件占用。 | 新环境可以按照同一条命令构建包和复跑检查。契约测试并行运行时不会串到其他实例，更新进度读取时的文件占用也更容易恢复。 |

## 数据库前后对照

每组使用 1,000 或 10,000 篇文献，每篇含 1 个标签、1 个附件和 8 条对话。每阶段测量 9 次并取中位数，SQL 计数单独采集。各版本使用相同的 SQLite 临时排序设置。装载计时为 `Store.load()`，包括组装卡片和内存缓存。评分计时为数据库与内存保存步骤。实际冷启动、浏览器渲染、文件传输以及首次索引创建的时间单独于这些数字。

| 指标 | 文献数 | 优化前 `565f1985` | P0 `9149b45` | P1 |
| --- | ---: | ---: | ---: | ---: |
| 装载 SELECT 次数 | 1,000 | 3,003 | 3,003 | 6 |
| 装载 SELECT 次数 | 10,000 | 30,003 | 30,003 | 6 |
| 装载中位数 | 1,000 | 75.05 ms | 73.58 ms | 58.44 ms |
| 装载中位数 | 10,000 | 901.16 ms | 920.56 ms | 780.32 ms |
| 一次评分的 SQL 写语句 | 1,000 / 10,000 | 15 | 16 | 2 |
| 一次评分的保存中位数 | 1,000 | 20.66 ms | 0.71 ms | 0.54 ms |
| 一次评分的保存中位数 | 10,000 | 212.19 ms | 1.07 ms | 0.80 ms |

1 万篇的装载相对 P0 从约 0.92 秒降到 0.78 秒，缩短约 15%。评分保存最明显的改善来自 P0 去掉全库哈希遍历，P1 又减少了 14 条 SQL 写语句。复测可使用 `python tools/bench_library.py --root <待测源码目录> --samples 9`。

## 浏览器实际操作对照

使用同一浏览器和两篇各 2 页的合成 PDF，对比 P0 和 P1。每个版本往返书库与详情 20 次，再打开一篇开始拖拽并直接离开。以页面监听注册及其移除状态计数。

| 场景 | P0 实测 | P1 实测 |
| --- | --- | --- |
| 最后一次进入详情后的活动拖拽监听 | 42 | 2 |
| 最后一次回到书库后的残留监听 | 42 | 0 |
| 拖拽分栏中切回书库 | 全页仍使用拖拽光标，文本选择仍被禁用 | 两项样式都恢复 |
| 旧详情请求在切到另一篇后故意延迟失败 | 旧请求报错盖掉当前文献 | 旧读取被取消，当前文献保留 |
| 阅读器打开合成 PDF | 渲染 2 页 | 渲染 2 页 |

最终工作区另做了交互检查。PDF 下一页按钮能从第 1 页切到第 2 页。引用窗和文件夹选择器都可按 Esc 关闭并留在当前文献。打开文件夹选择器后切回书库，弹层随页面移除。点第四颗星后界面显示「已打 4 分」，服务端再次读取该文献时评分为 4，PDF 关联仍在。

## 验证范围

- P0 验证包含同篇并发评分与状态编辑、SQLite 部分写入失败、升级验证期间拒绝写入、结构变更后的 SQLite 回滚、损坏备份拒绝恢复以及修复后重试。还验证了程序备份中断与重新安装时的用户编辑保留。
- P1 新增关联表加载、历史数据顺序、评分跳过关联表写入、旧路由取消和旧界面错误隔离的回归覆盖。首轮本地全量并跑偶发更新状态失败，修复临时文件替换后复跑完整脚本通过。
- Python 跳过真实旧库迁移和可选 `cryptography` 互验。API 契约的 13 项跳过由快照标记。本次使用合成库，未运行付费 AI，也未拿已发布旧客户端做正式在线升级。ZIP 冒烟验证覆盖解压后的便携进程和 HTTP 接口，界面交互使用本地 Edge。GitHub 托管 CI 等待代码推送后触发。
- 测试以已提交的 P0 和当时的 P1 工作区为对照，验收包在本机构建。

## 2026-11-19 本机打包复验

从仓库的 `tools` 目录运行时，便携 Python 继承的临时目录不可用，导致旧脚本把测试目录写到了仓库根目录。C# 也无法在原临时路径生成文件。另一次复跑发现，替换仓库内的便携运行时可能遇到旧 DLL 文件锁。

修正后的脚本先验证系统 Python、便携 Python 和 Windows PowerShell 对临时目录的访问，再把测试源码副本、便携运行时构建、编译和解包验证都放到仓库外。只将通过验包的 ZIP 和结果 JSON 写入产物目录。旧运行遗留的 62 个测试目录、半成品发布目录和运行时残留已保留在 `tmp/windows-check-failed-20261119-000940/`。

按原命令 `pwsh -File check_windows.ps1` 复跑通过，726 项 Python 测试中 724 项通过、2 项跳过，Node 测试通过。源码和解压包契约都得到 61 通过、0 失败、13 跳过。复跑后检查仓库根目录，未发现新增的测试目录。快速打包 `-PackageOnly` 也单独通过验包。
